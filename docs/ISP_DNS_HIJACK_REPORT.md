# 运营商 DNS 污染 + 广告注入 实测报告

> 本报告基于 WhaleyTV WTV55K1J（Android 5.0.2，WUI 2.0）在家庭宽带环境中的
> 实测取证。AdJustice 拦截证据与网络诊断均来自设备本地，未上传任何数据。

## 摘要

该宽带网络存在**系统性的 DNS 劫持**：运营商在 UDP 53 明文 DNS 通道上
对**所有公共 DNS 服务器**（223.5.5.5 / 114.114.114.114 / 119.29.29.29 /
8.8.8.8 / 1.1.1.1）的查询响应进行篡改（返回 malformed 或伪造响应）。
受影响期间，腾讯视频等应用的广告域名被解析到**海外广告服务器 IP**，
非法广告（保健品、赌博、诱导充值等）被注入播放。

**唯一安全的 DNS 通道是 TCP 53 与 DNS-over-HTTPS（DoH）**——实测
同一域名在 UDP 53 上被污染、在 TCP 53 / DoH 上返回正确结果。

## 一、DNS 劫持证据

### 1.1 UDP 53 全面污染

对 `vv.video.qq.com` 的解析对比（同一时刻、同一网络）：

| DNS 服务器 | UDP 53 | TCP 53 |
|---|---|---|
| 223.5.5.5（阿里） | malformed / 间歇性正常 | ✅ 3 answers |
| 114.114.114.114（114DNS） | malformed | ✅ 3 answers |
| 119.29.29.29（腾讯） | malformed | 连接被重置 |
| 8.8.8.8（Google） | malformed | 连接被重置 |

关键证据：**UDP 53 被篡改，TCP 53 返回正确结果**——证明污染发生在
UDP 明文 DNS 通道，而非 DNS 服务器本身。

### 1.2 域名级污染

- `btrace.qq.com`（腾讯埋点）→ `0.0.0.1`（异常）
- `cdn.qq.com`（正常 CDN 域名）→ `0.0.0.1`（异常）
- 路由器（192.168.x.1）作为 DNS 同样返回污染结果——**劫持在运营商出口，
  不在路由器**

### 1.3 DoH 正常

通过 DoH（`https://doh.pub/dns-query`）解析 `vv.video.qq.com`：
正常返回腾讯 CDN 节点（`ins-giuzhgwa.ias.tencent-cloud.net` →
42.81.178.72 / 42.81.178.232）。

## 二、广告注入证据

### 2.1 被劫持解析的广告服务器 IP

腾讯视频（`com.ktcp.video`）在广告播放期间直连以下 IP（均非腾讯 CDN）：

| IP | 归属 | 国家/运营商 |
|---|---|---|
| 201.234.234.61 | Level 3 | 委内瑞拉 |
| 154.174.194.154 | Scancom (MTN Ghana) | 加纳 |
| 85.223.202.42 | Kyivstar | 乌克兰 |
| 36.110.110.189 | Chinanet | 中国北京 |

这些 IP 在中国网络**不可达**（连接超时），但腾讯视频显示已建立连接——
典型的 TCP 层劫持/透明代理特征。

### 2.2 被拦截的广告域名

AdJustice 本地代理实测拦截（2026-07-31，共 50 次）：

| 域名 | 拦截次数 | 说明 |
|---|---|---|
| `tencent-dtv.m.cn.miaozhen.com` | 14 | **腾讯视频广告 SDK**（秒针系统广告监测）——HTTPS 隧道层阻断 |
| `*.aginomoto.com`（vod/passport/appstore/api/ad/rec） | 36 | Whaley 电视系统广告服务 |

### 2.3 注入特征

被拦截的 HTTP 响应含以下 ISP 注入特征：
- `Via: 1.1`（透明代理标记）
- `x-via: 1.1 inXX:XX (Cdn Cache Server V2.0)`
- `Server: openresty/1.27.1.2` + `x-ws-request-id`（疑似注入代理的
  自定义标记，正常源站不会同时出现这两者）

## 三、攻击链

```
用户播放视频
   │
   ▼
应用解析广告域名（ads.qq.com / miaozhen.com 等）
   │
   ▼
UDP 53 查询 → 运营商篡改响应 → 返回海外广告服务器 IP
   │
   ▼
应用直连被劫持 IP（绕过系统代理）→ TCP 层被透明代理接管
   │
   ▼
注入的非法广告内容（保健品/赌博/诱导充值）替换正常广告
```

## 四、AdJustice 的防护措施

1. **本地 HTTP 代理（127.0.0.1:8898）**：拦截走代理的明文 HTTP 流量，
   检测注入签名并替换为空响应
2. **TCP DNS 解析**：代理连接上游时改用 TCP 53 解析域名，绕过 UDP 污染
3. **广告域名黑名单**：在 HTTPS 隧道建立前阻断已知广告域名
   （`miaozhen.com` 等），导致广告 SDK 加载失败
4. **可疑 IP 黑名单**：阻断解析到已知广告服务器 IP 的连接

### 局限

无 root 权限无法强制所有流量走代理。部分应用（如腾讯视频）会绕过
系统代理自行解析 DNS 并直连，此类流量无法被代理拦截（已实测发现）。

## 五、建议

### 对用户
1. 使用支持 DNS-over-HTTPS/TLS 的路由器（如 OpenWrt + https-dns-proxy）
2. 或让应用使用 DoH 解析
3. 向运营商投诉 DNS 劫持（工信部 12321）

### 对开发者
1. 应用内应使用 DoH/TCP DNS，不依赖系统 UDP DNS
2. 广告 SDK 域名应走 HTTPS 且校验证书
3. 检测到解析到非预期地域的 IP 时应拒绝连接
